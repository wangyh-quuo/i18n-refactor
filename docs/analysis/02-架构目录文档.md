## 4. 项目现有代码书写风格（基于源码）

1. **模块**：ESM；类型多用 `import type`；部分 `export default`（Scanner、config、babelTraverse）。
2. **命名**：类 PascalCase（`ScriptParser`、`Replacer`）；函数 camelCase；接口 `I` 前缀（`IConfig`、`IParser`、`IContext`）；常量 UPPER_SNAKE（`DEFAULT_SOURCE_DIR`）。
3. **注释**：JSDoc 常见于 generator/utils；中文行内注释说明业务场景（如模板字符串示例）。
4. **类 vs 函数**：Parser/Replacer/Scanner 用 class；key/json/工具多为纯函数；`parserFactory` 为带 static 的 class（类名小写开头，与常见 PascalCase 不一致，属现状）。
5. **类型宽松点**：`Record<string, any>`、`source?: any`、CLI `options?: Record<string, any>` 并存于严格 tsconfig。
6. **错误处理**：多为存在性判断后静默跳过或 `console.warn/log`；无统一 try/catch 框架。
7. **测试风格**：mocha + assert；直接改 `rawContent` / `setTemplateContent` 测 process；期望值内嵌 `getKeyByText(..., 'common')`。

## 6. 历史特殊业务坑点（代码中已体现）

1. **语义安全 / 少替**：README 与实现一致——含 HTML 的模板字符串、混合 CompoundExpression 记入 `notReplaceFiles`，不自动替换。
2. **Import / Object key 跳过**：`StringLiteral` 在 `ImportDeclaration` 或非 computed 的 `ObjectProperty` key 上跳过。
3. **插值限制**：脚本模板字符串仅当表达式全为 `Identifier` | `MemberExpression` 才整段替换为 `t(key, {0:..})`；否则对 quasi 片段单独 `\${t(...)}`。
4. **Vue 属性**：静态中文属性先加 `:` 再把值换成 `"$t('key')"`。
5. **scriptSetup 优先**：`descriptor.scriptSetup || descriptor.script`，无 setup 才用 script。
6. **条件/数组表达式偏移**：`handleConditionalExpression` / `handleArrayExpression` 用 `node.loc.start.offset - 1` 等手工修正位置（易错敏感区）。
7. **中文正则不一致**：utils/scanner 用 `\u4e00-\u9fa5`；scriptParser 部分用 `\u4e00-\u9fff`。
8. **scan 两种路径**：自动替换用 `fast-glob`（含 jsx/tsx）；`--scan` 用同步递归，扩展名仅 `vue|js|ts`，不含 jsx/tsx。
9. **dryRun**：不写源文件，但 `writeJsonToFile` 在 `run` 末尾仍会执行（无 dryRun 短路），可能仍写 locales/excel。
10. **`initExistingKeys` 假定两层结构**：`existingJson[module][key] = text`，更深嵌套或扁平结构可能映射不全。
11. **`babelTraverse` 兼容层**：专门处理 CJS/ESM 双 default，勿随意改成直接 import。
12. **`parserFactory` 类名小写**：历史命名，新增应对齐或保持引用不变。
13. **用户附件关注点**：`scriptParser.ts` 模板字符串替换串 `` `\${t('${key}', { ... })}` `` — 属于 TemplateLiteral 分支产物形态。
