# 禁止修改清单

> 依据：规则2「修改红线」+ 本仓库实际角色。下列文件/目录在无用户明确指令时视为禁止或高风险改动。

## 1. 严禁改动（底层配置 / 构建 / 依赖锁 / 产物）

| 路径 | 原因 |
|------|------|
| `package.json` | 依赖版本、bin、scripts、包元数据；属第三方依赖与工程入口配置 |
| `package-lock.json` | 锁定树；非需求明确升级勿动 |
| `tsconfig.json` | 全局编译/类型约束；属底层配置 |
| `rollup.config.js` | 构建入口与产物形态 |
| `.mocharc.json` | 测试运行器底层配置 |
| `.gitignore` / `.npmignore` / `.gitattributes` | 工程基础设施 |
| `node_modules/**` | 第三方依赖源码，严禁改动 |
| `dist/**` | 构建产物；应由 `npm run build` 生成，勿手改 |

## 2. 高风险核心（无明确需求勿改；改则需评估全链路）

| 路径 | 原因 |
|------|------|
| `packages/core/context.ts` | 全局运行时状态单例；属核心常量/上下文 |
| `packages/config/index.ts` | 默认配置与 `IConfig` 契约；类似核心常量 |
| `packages/utils/babelTraverse.ts` | CJS/ESM 兼容层；误改导致 traverse 运行失败 |
| `packages/core/init.ts` | 配置发现与合并、已有 JSON 初始化；影响全流程入口 |

说明：若后续需求明确要求改配置项默认值或 CLI 选项，再单列变更；默认按禁止修改处理。

## 3. 业务核心（可按需求改，但属敏感；禁止「顺手重构」）

以下不是「绝对禁止」，而是规则2边界下：**无用户明确指令不重构、不格式化、不删减**；仅允许需求相关增量。

| 路径 | 敏感点 |
|------|--------|
| `packages/parser/scriptParser.ts` | 模板字符串/字符串替换语义；偏移与 `t()` 形态 |
| `packages/parser/vueParser.ts` | template 偏移修正、复合/条件/数组表达式 |
| `packages/generator/keyGenerator.ts` | key 稳定性、已有文案复用 |
| `packages/generator/jsonGenerator.ts` | 合并写盘，影响 locales |
| `packages/replacer/index.ts` | 写文件与 MagicString |
| `packages/core/run.ts` | 编排顺序；dryRun/scan 分支 |
| `packages/scanner/index.ts` | 扫描规则与扩展名差异 |

## 4. 建议默认不动的外围文件

| 路径 | 原因 |
|------|------|
| `README.md` | 文档；非用户要求不改 |
| `test/i18nHelper.spec.ts` | 除非需求要求补测/修测；禁止无关格式化 |
| `docs/analysis/**` | 本轮分析文档；开发阶段不当作业务代码改 |

## 5. 修改红线复述（执行约束）

1. 严禁改动底层配置、全局拦截器（本项目无 HTTP 拦截器）、核心常量、第三方依赖源码。  
2. 无用户明确指令：不重构、不优化、不格式化、不删减存量旧代码。  
3. 只增量改需求相关文件；无关代码原样保留。  
4. 进入规则3开发前，须人工核对本文档与另外三份分析文档无理解偏差。

## 6. 待人工确认项（分析阶段存疑，请核对）

1. `dryRun` 是否应阻止写 `zh.json` / Excel？（现状仍写）  
2. `--scan` 是否应与 `scan()` 一样支持 `jsx/tsx`？  
3. 中文正则 `\u9fa5` vs `\u9fff` 是否有意区分？  
4. 用户是否已有具体功能需求（例如修正 `scriptParser` 模板字符串 replacement 形态）？规则1完成后需明确需求再拆解。  
5. `docs/analysis` 是否保留在仓库内，或仅作对话交付？
